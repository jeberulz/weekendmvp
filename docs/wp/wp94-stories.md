# WP94 — Collaborative crew assignments

First release implements the audit's Iris-to-Elle loop in the existing workspace. Planned roles keep their current availability. Connector integration and activation of new specialist capabilities are subsequent work packages.

1. A founder change request starts a durable revision through the real queue. Existing queued revisions can be recovered without duplicate runs or debits.
2. The lead and Team HQ read actual role availability and revision state. The lead's receipt follows the database transaction.
3. The founder can start a supported assignment from chat, including against the current approved artifact. The command remains bounded by workspace access, capability, budget and approval rules.
4. A requested email follow-up receives the approved brand version. The founder can follow the work through the request, brand review and email review. Record input versions and surface changed inputs that affect existing copy.
5. Exercise the public entry points, retry and recovery against an isolated fixture. Run the repository checks before a deployment decision.

Workspace UX uses the existing lead thread, Team HQ and artifact review surfaces. Internal drafts and explicit approvals retain their existing scope.
