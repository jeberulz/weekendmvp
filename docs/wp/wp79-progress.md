## 2026-11-06 — Draft contact revocation hook

- `internal.growth.email.contacts.revokeLeadContact({ leadId })` is designed for WP78 to call inside its owner-authorized lead deletion mutation, before clearing contact fields. It is internal and does not enqueue mail. It finds at most one active enrollment through `by_leadId_and_state`, checks at most the frozen four sends for that enrollment, cancels waiting/queued component mail, revokes the enrollment, cancels a queued opt-in confirmation linked on the token row, and deletes opt-in/unsubscribe token hashes. Historical send/enrollment rows retain IDs and status but no recipient email/body; future sender code must keep `failureCode` and other retained metadata free of contact PII. The lead's email/payload/source are erased by WP78. Component finalized rows follow the owner-approved seven-day cleanup; provider sent content/logs may remain 30 days in the US and must be disclosed.
- Future enrollment creation must enforce one active enrollment per lead and four send rows per enrollment; token issuance must keep one row per purpose. Any transition out of `active` (including pause and completion) must first cancel or finalize queued component mail. The active-only deletion query is safe only after those sender/transition invariants and integration tests land. WP78 real capture and hard purge remain off until that proof and the owner deletion call are merged.
- The hook refuses over-limit active rows or token rows and aborts the owner deletion transaction; it never silently leaves queued mail behind. If legacy/corrupt rows violate an invariant, operators must repair/cancel those rows in bounded transactions and retry deletion. That repair path is not implemented, so capture remains gated. A missing component email row means it was already removed and cannot send; unexpected component query/cancel errors abort all cancellations and token changes.
- Focused local component tests cover two enrollments (one historical, one active), queued versus submitted mail, queued confirmation cancellation, idempotent retry, cleaned-up missing component row, component-error rollback, and over-limit active enrollment/send rows. `npx vitest run convex/growth/email/contacts.test.ts` (5 pass), `npm run typecheck` (pass), focused ESLint (pass); full exact-head gate and independent review still required.
