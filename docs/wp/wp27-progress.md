### Frozen-contract conflict found and escalated

Under the frozen schema there was literally nowhere to store an anonymous preview artifact.

### Owner rulings obtained

- **Anonymous storage:** add one additive `preview_capabilities` table. Chosen over relaxing `ownerId` to optional on `site_configs`/`site_versions` (which would weaken the owner-only authorization invariant on tables whose security gate already passed, forcing a re-review of every authz path) and over ephemeral no-persistence rendering (which contradicts "signup keeps it" and would make `/preview/{token}` meaningless).
- **Capability lifetime:** 7 days, reusable within the window. Chosen over 24 hours, which would kill the realistic come-back-later conversion, and over 30 days, which weakens "expiring" as a security property.
- **Template set:** three templates with a picker. This went against the recommendation of one template; the trade-off was stated in the question (triples the renderer surface, XSS/schema test matrix, and accessibility review inside a 10-day launch window) and the owner chose it with that in view. The cost is concentrated in `S3` and is written into the story as a **per-template** security and accessibility matrix rather than a single shared suite.

### Architecture decisions taken by the orchestrator (not owner rulings)

- **`SiteRenderSpec` wrapper resolves the template-storage question without a second schema change.** The three-template choice implied storing a template selection somewhere, and neither the frozen `site_configs` nor WP26-S1's frozen `SiteInputPayload` has a field for it. Rather than amend either, WP27 defines `SiteRenderSpec = { contractVersion, templateId, siteInput }` stored as the site version's `documents.body`. Template choice is a rendering property, not content, so this is also the correct home for it on the merits — and it carries the selection through the anonymous-to-claimed transition at no extra cost.
- **Capability tokens are stored hashed**, never in plaintext, mirroring the discipline WP21 applied to magic-link tokens. A database read must not be able to reconstruct a working preview URL.
- **Token resolution is constant-shape.** Expired, unknown, and malformed tokens are indistinguishable to the caller so the endpoint cannot be used to enumerate valid capabilities.

- Token design: 32 bytes of `crypto.getRandomValues` (256 bits), hex-encoded, stored only as a SHA-256 hash. Web Crypto rather than `node:crypto` because the latter would require `"use node"`, which cannot coexist with queries and mutations in one file per the Convex guidelines. A slow KDF is deliberately not used: those exist for low-entropy secrets, and a 256-bit random token is not one.
- `resolveCapability` returns `null` identically for malformed, unknown, and expired tokens, so a caller cannot learn that a token was once valid.

## 2026-08-06 - WP27-S1 independent security review: one real fail-open found and fixed

- Reviewed by a separate agent with no memory of writing the code, briefed to try to break it rather than confirm it. It ran the suites independently and probed token entropy, normalization, timing, expiry, the template enum, fail-closed behavior, the additive-schema claim, and test quality.
- **Critical finding, fixed: expiry failed open on a non-finite clock.** `expiresAt <= NaN` evaluates to `false`, so `isCapabilityExpired` reported *every* expired capability as live. Convex `v.number()` is a float64 and admits `NaN`, so had `S2`/`S4` followed the Convex guideline's literal advice to "pass the current time in as an argument", an anonymous visitor could have revived any expired preview by sending `NaN`. Verified the bug empirically before and after rather than reasoning about it alone. Fixed by failing closed on any non-finite `now`, in both `isCapabilityExpired` and before the lookup in `resolveCapability`, with regression tests covering `NaN` and both infinities against expired and live capabilities.
- **Fixed: `.unique()` could turn a data bug into a permanent anonymous-facing 500.** Convex indexes carry no uniqueness constraint, so two rows sharing a `tokenHash` would make `.unique()` throw — a louder, distinguishable signal than not-found. Now caught and collapsed to `null`.
- **Fixed: error-class-based catch was fragile.** The spec-parse catch previously rethrew anything that was not a `ConvexError`. Nothing leaks today, but one future refactor throwing a `TypeError` would have turned a corrupt row into a 500 an anonymous caller could distinguish from not-found. Now caught broadly and deliberately, with the reasoning recorded at the call site.
- **Fixed: the timing claim was overstated.** The code asserted resolution was indistinguishable; the honest claim is constant *shape*, not constant *time* — malformed returns before any read, unknown costs an index miss, a live hit additionally parses. Corrected in the comment, with the residual accepted (exploiting it requires already holding a 256-bit token) and the observable half of the obligation pushed to `S4`, which must not vary status code, body, or cache headers.
- **Fixed: two tests could pass for the wrong reason.** Rejection tests asserted only `toThrow(ConvexError)` and would have passed if the throw came from an unrelated check; they now assert specific error codes. A test named "without a database read" never observed the database; it now injects a ctx whose `db.query` throws, so it genuinely proves the shape check short-circuits first.
- **Fixed: the 256 KiB ceiling was enforced only on write.** The schema stores `renderSpec` as a bare `v.string()` and cannot compel a writer to use `serializeSiteRenderSpec`, so an oversized row would have parsed happily on every anonymous read. The ceiling now also holds on parse.
- **Accepted, not fixed, and pushed to the stories that own it:** the parser returns the parsed object as-is, so unknown keys survive validation. This matches WP26-S1's existing convention, so changing it here would diverge the two sibling contracts. It is harmless to a reader of named fields and load-bearing to anything that spreads the object onto an element, so `S3` now carries an explicit constraint to read only named fields and never iterate or spread the spec. `S2` likewise now carries explicit constraints to persist only through `serializeSiteRenderSpec` and to source `now` from a server `Date.now()`.
- Confirmed holding under probing, with no change needed: token entropy and unsalted SHA-256 (correct for a high-entropy secret; no length-extension exposure), normalization against unicode and case attacks (Kelvin sign, fullwidth digits, Turkish dotted capital, BOM/NBSP padding all rejected by the hex shape gate), the closed template enum against prototype and `toString` tricks, the absence of any partial-render path, and the additive-schema claim.
- Final evidence after fixes: `npx vitest run convex/platform/preview/preview.test.ts` — 23 passed; `npm run typecheck` pass; `npx eslint convex/platform/preview/` pass, 0 findings; `npm test` pass, 46 files / 516 tests; `npm run build` pass, 310 pages; `npm audit --omit=dev --audit-level=high` 0 vulnerabilities; `git diff --check` clean; secret scan on the new files, no matches.
- Note: an earlier typecheck failure caught a hand-rolled structural ctx type that did not match Convex's real `QueryCtx`. Replaced with the `Pick<QueryCtx, "db">` convention already used by `platform/authz.ts` — the codebase already had the right pattern and it should have been used first.

## 2026-08-06 - WP27-S3 implemented (three templates)

- Added `components/preview/templates/index.tsx` (Editorial, Product, Minimal plus a closed dispatch table) and `components/preview/templates/PreviewWatermark.tsx`, with the per-template security matrix at `tests/security/wp27-templates.test.tsx`.
- **Finding that changed the story's shape: `SiteInputPayload` v1 carries no URL-valued field.** Every value is text, and `citations` are numeric positions into `document_citations`, not links. The story's acceptance criterion "any URL-valued field is protocol-allowlisted" therefore has no attack surface to guard in v1. Rather than sanitize a URL that does not exist — or quietly skip the criterion — the templates implement the stronger structural property: no template constructs an `href`, `src`, `action`, or `formaction` from spec content at all, and a test asserts that per template by rendering a marker into every field and proving it appears in no navigable attribute. A future URL field cannot introduce one without failing that test.
- Three rules hold across all three templates, each asserted per template rather than once for the set (the accepted cost of the owner's three-template ruling): named-field reads only (never iterating or spreading the spec, which matters because WP26-S1's parser lets unknown keys survive validation), no raw markup anywhere, and no caller-derived URLs. A dedicated test contaminates the spec with `evil`/`rogue` keys and proves neither renders.
- The watermark is structural, not a prop: templates take no argument that could suppress it. The decorative mark is `aria-hidden` with a separate readable `PreviewNotice`, so hiding the visual stripe from assistive technology does not hide the *fact* of the preview.
- The call to action is deliberately an inert `<button type="button">`, never an `<a>` or `<form>`. A preview must not be able to navigate a visitor anywhere, and this is the seam through which a lead-capture path could later regress; a test asserts no `<form>` and no link CTA per template.
- **The security suite was mutation-tested rather than assumed effective.** Temporarily replacing one template's subheadline with `dangerouslySetInnerHTML` produced 6 failures; restoring it returned all 48 to green. A suite that cannot fail is not evidence.
- One false positive of my own was found and fixed while writing it: the first event-handler assertion regex-matched the raw HTML string, which flags the *escaped* text `onerror=&quot;` inside correctly-neutralised content. React had escaped the payload properly; the test was wrong, not the renderer. It now extracts real tags and checks only those.
- **Honest scope limit on accessibility:** `S3` asserts the structural properties provable without a route — exactly one `main`, exactly one `h1`, `h1` first in document order, inert CTA, `aria-hidden` decorative watermark. ## 2026-08-06 - WP27-S4 implemented (`/preview/{token}`)

- Added `app/preview/[token]/{page,not-found}.tsx`, `components/preview/PreviewViewed.tsx`, the `convex/platform/preview/read.ts` read path, a `/preview/:token` header rule in `next.config.ts`, and two suites: `convex/platform/preview/read.test.ts` (8) and `tests/security/wp27-preview-route.test.mjs` (13).
- **The clock forced the read path's shape.** The Convex guidelines forbid reading the wall clock inside a query, but the obvious alternative — a public query taking `now` as an argument — is worse than stale data: expiry *is* the entire authorization for an anonymous capability, so a caller supplying `now` picks their own expiry and can revive a week-old token by calling Convex directly with `now: 0`. Resolved with a public `action` that reads `Date.now()` itself and delegates to an `internalQuery` that trusts it. `read.test.ts` demonstrates both halves: the internal query really does resolve an expired capability when handed `now: 0`, and the public action rejects the argument outright (`Unexpected field \`now\``, enforced by the validator and by TypeScript).
- **Constant observable outcome, measured not asserted.** At equal token length the live responses for an expired capability, a well-formed unknown token, and a malformed token are **byte-identical**, with identical `Cache-Control`, `X-Robots-Tag`, `Referrer-Policy`, `Content-Type`, and `Vary`. The sanity control passes too: a valid token's body differs, so the comparison can detect a difference. The expired case was produced honestly by temporarily setting `CAPABILITY_LIFETIME_MS` to `1`, generating a token, and restoring the constant (`git diff` on that file is clean).
- **Known deviation — the route answers 200, not 404.** Under Cache Components the route still emits a Partial Prerendering shell, which is flushed with its 200 before the dynamic part runs, so `notFound()` renders the generic page but cannot set the status. Awaiting `connection()` was tried and did not suppress the shell (`x-nextjs-postponed` stayed set), so it was removed rather than left in as dead code that a comment would have to lie about. This is a soft-404, not a leak: *all four* cases — valid, unknown, expired, malformed — answer 200, so there is no status oracle at all, which is stronger than the story required. Non-indexability rests on `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet, noimageindex` plus the robots metadata, not on the status code. Flagged for `S6` in case the owner wants a real 404.
- **Headers live in `next.config.ts`, not the page, for a security reason.** Headers set inside the page would apply only to a successful render, which would make `Cache-Control` itself the oracle that the single `notFound()` path exists to close. The path-matched rule covers the not-found responses too — verified live.
- **Not cached across tokens:** three tokens rendered three different templates on the same route in the same process, and failures rendered the not-found body; `Cache-Control: private, no-store, max-age=0` was returned in every case. The prerendered shell is token-independent by construction — everything capability-derived is in the dynamic part.
- **Origin gate carried over from `S2` and fixed.** The old check read `PLATFORM_BILLING_APP_ORIGIN` (a billing-named variable governing a preview route) and skipped entirely when unset, so the default deployment ran with no gate and nothing said so. `isAllowedPreviewOrigin` now always compares a present `Origin` against something: the new optional `PLATFORM_PREVIEW_APP_ORIGIN` when set, otherwise the request's own `Host`, which a browser sets from the URL being fetched and page script cannot forge. An unparseable `Origin`, or one with no `Host` to compare against, fails closed. An absent `Origin` still passes — deliberate, and the bridge signature remains the real authority.

### Findings acted on

- **HIGH — the capability token was being shipped to Google and Meta.** `app/layout.tsx` renders `<AnalyticsScripts />` on every route, and GA4's automatic `page_view` sends `page_location = document.location.href`.
