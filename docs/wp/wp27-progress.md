### Owner rulings obtained

- **Anonymous storage:** add one additive `preview_capabilities` table. Chosen over relaxing `ownerId` to optional on `site_configs`/`site_versions` (which would weaken the owner-only authorization invariant on tables whose security gate already passed, forcing a re-review of every authz path) and over ephemeral no-persistence rendering (which contradicts "signup keeps it" and would make `/preview/{token}` meaningless).
- **Capability lifetime:** 7 days, reusable within the window. Chosen over 24 hours, which would kill the realistic come-back-later conversion, and over 30 days, which weakens "expiring" as a security property.
- **Template set:** three templates with a picker. This went against the recommendation of one template; the trade-off was stated in the question (triples the renderer surface, XSS/schema test matrix, and accessibility review inside a 10-day launch window) and the owner chose it with that in view. The cost is concentrated in `S3` and is written into the story as a **per-template** security and accessibility matrix rather than a single shared suite.

### Architecture decisions taken by the orchestrator (not owner rulings)

- **`SiteRenderSpec` wrapper resolves the template-storage question without a second schema change.** The three-template choice implied storing a template selection somewhere, and neither the frozen `site_configs` nor WP26-S1's frozen `SiteInputPayload` has a field for it. Rather than amend either, WP27 defines `SiteRenderSpec = { contractVersion, templateId, siteInput }` stored as the site version's `documents.body`. Template choice is a rendering property, not content, so this is also the correct home for it on the merits — and it carries the selection through the anonymous-to-claimed transition at no extra cost.
- **Capability tokens are stored hashed**, never in plaintext, mirroring the discipline WP21 applied to magic-link tokens. A database read must not be able to reconstruct a working preview URL.
- **Token resolution is constant-shape.** Expired, unknown, and malformed tokens are indistinguishable to the caller so the endpoint cannot be used to enumerate valid capabilities.

## 2026-08-06 - WP27-S1 implemented

- Added `convex/platform/preview/renderSpec.ts` (the `SiteRenderSpec` contract and closed template enum), `convex/platform/preview/capabilities.ts` (token generation, hashing, expiry, constant-shape resolution), and `convex/platform/preview/preview.test.ts`.
- Schema change is **purely additive and verified as such**: `git diff --stat convex/schema.ts` reports 31 insertions and **zero deletions**, i.e. one import line plus the one ruled `preview_capabilities` table. No existing table, index, or validator was touched. The WP22 frozen-contract test (`convex/platform/contracts.test.ts`) still passes — it asserts a named 16-table inventory with `arrayContaining` index checks and never asserts a total table count, so a 17th table does not violate the freeze.
- The template enum lives in the new WP27-owned `renderSpec.ts` rather than the WP22-frozen `platform/validators.ts`, so WP27's only edit to a frozen file is the authorized schema table. Verified no import cycle: `renderSpec.ts` pulls only `convex/values`, `platform/engine/contracts`, and `platform/validators`, none of which import `schema` or `_generated`.
- Token design: 32 bytes of `crypto.getRandomValues` (256 bits), hex-encoded, stored only as a SHA-256 hash. Web Crypto rather than `node:crypto` because the latter would require `"use node"`, which cannot coexist with queries and mutations in one file per the Convex guidelines. A slow KDF is deliberately not used: those exist for low-entropy secrets, and a 256-bit random token is not one.
- `resolveCapability` returns `null` identically for malformed, unknown, and expired tokens, so a caller cannot learn that a token was once valid.

## 2026-08-06 - WP27-S1 independent security review: one real fail-open found and fixed

- Reviewed by a separate agent with no memory of writing the code, briefed to try to break it rather than confirm it. It ran the suites independently and probed token entropy, normalization, timing, expiry, the template enum, fail-closed behavior, the additive-schema claim, and test quality.
- **Critical finding, fixed: expiry failed open on a non-finite clock.** `expiresAt <= NaN` evaluates to `false`, so `isCapabilityExpired` reported *every* expired capability as live. Convex `v.number()` is a float64 and admits `NaN`, so had `S2`/`S4` followed the Convex guideline's literal advice to "pass the current time in as an argument", an anonymous visitor could have revived any expired preview by sending `NaN`. Verified the bug empirically before and after rather than reasoning about it alone. Fixed by failing closed on any non-finite `now`, in both `isCapabilityExpired` and before the lookup in `resolveCapability`, with regression tests covering `NaN` and both infinities against expired and live capabilities.
- **Fixed: `.unique()` could turn a data bug into a permanent anonymous-facing 500.** Convex indexes carry no uniqueness constraint, so two rows sharing a `tokenHash` would make `.unique()` throw — a louder, distinguishable signal than not-found. Now caught and collapsed to `null`.
- **Fixed: error-class-based catch was fragile.** The spec-parse catch previously rethrew anything that was not a `ConvexError`. Nothing leaks today, but one future refactor throwing a `TypeError` would have turned a corrupt row into a 500 an anonymous caller could distinguish from not-found. Now caught broadly and deliberately, with the reasoning recorded at the call site.
- **Fixed: the timing claim was overstated.** The code asserted resolution was indistinguishable; the honest claim is constant *shape*, not constant *time* — malformed returns before any read, unknown costs an index miss, a live hit additionally parses. Corrected in the comment, with the residual accepted (exploiting it requires already holding a 256-bit token) and the observable half of the obligation pushed to `S4`, which must not vary status code, body, or cache headers.
- **Fixed: two tests could pass for the wrong reason.** Rejection tests asserted only `toThrow(ConvexError)` and would have passed if the throw came from an unrelated check; they now assert specific error codes. A test named "without a database read" never observed the database; it now injects a ctx whose `db.query` throws, so it genuinely proves the shape check short-circuits first.
- **Fixed: the 256 KiB ceiling was enforced only on write.** The schema stores `renderSpec` as a bare `v.string()` and cannot compel a writer to use `serializeSiteRenderSpec`, so an oversized row would have parsed happily on every anonymous read. The ceiling now also holds on parse.
- **Accepted, not fixed, and pushed to the stories that own it:** the parser returns the parsed object as-is, so unknown keys survive validation. This matches WP26-S1's existing convention, so changing it here would diverge the two sibling contracts. It is harmless to a reader of named fields and load-bearing to anything that spreads the object onto an element, so `S3` now carries an explicit constraint to read only named fields and never iterate or spread the spec. `S2` likewise now carries explicit constraints to persist only through `serializeSiteRenderSpec` and to source `now` from a server `Date.now()`.
- Confirmed holding under probing, with no change needed: token entropy and unsalted SHA-256 (correct for a high-entropy secret; no length-extension exposure), normalization against unicode and case attacks (Kelvin sign, fullwidth digits, Turkish dotted capital, BOM/NBSP padding all rejected by the hex shape gate), the closed template enum against prototype and `toString` tricks, the absence of any partial-render path, and the additive-schema claim.
