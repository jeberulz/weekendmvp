## The Problem

You watched a hundred tutorials. Every concept was explained. But when the cursor blinks on an empty file, nothing comes. The gap between following along and knowing how to code is wider than any video can close, and it is the single most common complaint in learning communities. r/learnprogramming has 4.3 million members, and a huge share of the threads are some version of the same question: I finished the course, so why can I still not build anything on my own?

AI made the gap worse, not better. Autocomplete and chat assistants made shipping easier and made learning optional. The code gets written. The understanding does not. The crutch becomes permanent. New developers paste in a working function they could not write themselves and could not debug if it broke, because no tool ever told them why it works.

The pain is acute and increasing. Self-taught developers and bootcamp graduates can assemble an app from snippets but freeze when an interviewer asks them to explain a loop, or when a production bug lands and the AI that wrote the code is no help reading it. They do not need another tool that writes code faster. They need one that makes them better.

## The Solution

Code Coach lives in the editor and teaches as you work. It is not a chatbot in a separate tab. Highlight a function you do not understand and get a plain-English breakdown of what it does and why. Hover over an error and see what caused it and how to fix it, with the reasoning, not just the patch. Write a loop that works but feels wrong and learn why it is inefficient and what is better.

The extension watches for the moments that matter: long pauses, repeated errors, and code that runs but is fragile. When it spots one, it offers a short, contextual explanation tied to the exact line on screen. The teaching happens inside the work, not in a course you switch to and forget. It starts with Python, the most common first language, then expands to JavaScript, React, and data science.

**How it works:**

1. Scaffold a VS Code extension with a command that sends the highlighted code and surrounding context to Claude and renders the explanation inline.
2. Add the core teaching loop: detect errors and pauses, then surface a why-focused explanation tied to the exact line, with a follow-up question prompt.
3. Ship a landing page with a 60-second demo GIF and a free Python tier, then gate advanced languages and saved learning paths behind Pro.

## Competitive Landscape

The big assistants are adjacent, not competitive. They make experienced developers faster; they do not teach beginners why. That leaves an open lane for a learning-first tool that lives in the same editor.

- **GitHub Copilot** ($10/mo) — Best-in-class autocomplete, but writes code without explaining the why. Speeds up people who already understand.
- **Cursor** ($20/mo) — A productivity-first AI editor. Powerful for shipping, not designed to teach the underlying logic.
- **Codecademy** ($17.49/mo) — Strong structured courses, but learning happens off to the side, not inside the project you actually care about.
- **Exercism** (Free) — Great mentored exercises, but the teaching is on curated problems, not the messy code in your own repo.

**Your Opportunity**

No existing tool teaches inside your own code, in real time, focused on why it works. Tight VS Code integration plus a learner-first explanation engine is hard to copy because the incumbents are committed to a productivity story.

## Recommended Tech Stack

This is a weekend-buildable extension, not a research project. The hard part is product judgment about when to teach, not exotic infrastructure. Lean on a fast, cheap model for the high-frequency explanations and reserve a stronger model for deep dives.

- **VS Code extension (TypeScript)** (Client) — Meets learners where they already work and ships through the Marketplace for instant distribution.
- **Claude (Haiku for inline, Sonnet for deep dives)** (AI) — Strong code reasoning and plain-English explanations; Haiku keeps per-explanation cost and latency low.
- **Local AST parsing + selection context** (Context) — Sends only the relevant code and surrounding scope, so explanations stay accurate and cheap.
- **Supabase + Stripe + PostHog** (Backend) — Auth, usage metering, billing, and product analytics with almost no server code to maintain.

**1. Project Setup**

```text
Build the weekend MVP of "Code Coach": a VS Code extension that explains the code you select in plain English, with the why and not only the what.

Stack: a VS Code extension in TypeScript, the Claude API for explanations, and VS Code's own storage for settings. Python is the only language this weekend. No login and no server.
Settings: an API key, a model name and the pause length, read from the extension settings.

Data (kept in VS Code globalState, no database):
- explanations(id, code_hash, language, trigger, response, created_at)
- triggers(kind, enabled)  where kind is one of error, pause, fragile
- settings(api_key, model, pause_seconds)

Commands: Explain This.
Env vars (names only): none. The API key is a VS Code setting.

Do not build: billing, usage caps or upgrade prompts, languages other than Python, accounts, a web app.
Done when: you can press F5 to open a test window, select a Python function, run Explain This and see the answer in a hover and a side panel.
```

**2. Core Feature**

```text
Build the one feature that proves Code Coach: the teaching loop.
1. Watch the active editor for three triggers: a diagnostic error on the current line, a pause of 8 or more seconds after typing, and code that runs but looks fragile (a bare except, a mutable default argument, a loop that rebuilds a list on every pass).
2. For each trigger, send the selection, its enclosing function and the language to Claude. Ask for a plain-English explanation of WHY, tied to the exact line, that ends with one follow-up question.
3. Show the answer in an inline hover and in a side panel.
4. Allow one call per 5 seconds. Cache each answer by code hash in explanations so the same code is never sent twice.
Rules: send only the selection and its enclosing function, never the whole file.
Empty state: with no API key, show one message that opens the settings.
Done when: a Python error on a line produces a why-focused explanation within a few seconds, and selecting the same code again answers from the cache.
```
