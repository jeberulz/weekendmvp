## The Problem

E-commerce brands pour money into paid ads — U.S. digital ad spend topped $240 billion in 2024 alone — but most of that traffic lands on generic product pages or quickly-built landing pages that bleed conversions. Manual page creation eats days of designer and developer time, and the iteration cycle for testing new offers is painfully slow. The result: lower ROAS, climbing customer acquisition costs, and growth-stage brands stuck waiting on agencies to ship a page.

Existing tools force a brutal trade-off. Drag-and-drop builders like Wix and Squarespace are too generic and miss conversion fundamentals. Enterprise platforms like HubSpot ($800-$3,600/mo) gate AI features behind enterprise pricing. Conversion specialists like Unbounce ($99-$649/mo) deliver power but ship a steep learning curve that small teams can't absorb. Marketers in r/marketing and r/ChatGPTPro consistently complain that current AI builders either over-promise on personalization, break on CMS integration, or produce designs that look templated. There's a clear gap for an e-commerce-first builder that respects both conversion craft and the speed solo operators need.

## The Solution

An AI landing page builder purpose-built for e-commerce campaigns. The user feeds in product details, target audience, and a campaign goal — the AI generates a fully responsive page with persuasive copy, optimized layout, and a visual hierarchy designed to convert. One-click integrations push the page to Shopify, WordPress, or a managed subdomain. As traffic flows, built-in A/B testing learns which elements move the needle and updates layouts automatically. Marketers stop waiting on designers, and brands spending $5K+/month on ads see CAC drop within weeks.

**How it works:**

1. **Describe** — Capture product, audience, and campaign goal in a guided wizard
2. **Generate** — AI builds copy, layout, and visuals tuned for conversion
3. **Connect** — Publish to Shopify, WordPress, or a managed subdomain
4. **Optimize** — A/B testing learns what converts and updates layouts

## Recommended Tech Stack

This stack lets a solo developer ship a working MVP in a weekend. Next.js handles the page editor and generated-page rendering, GPT-4o powers copy + layout planning, and Supabase covers auth, storage, and analytics events without standing up infrastructure.

- **Next.js 14 + TypeScript** — App Router for the editor, edge functions for serving generated pages with low latency.
- **OpenAI GPT-4o** — Copy generation, layout planning, and conversion-aware section selection. Use structured outputs for reliable JSON.
- **Tailwind CSS + Headless UI** — Renders the AI-generated pages with a curated component library so output stays on-brand and fast.
- **Supabase** — Postgres for pages and analytics events, auth for accounts, edge functions for the publish pipeline.
- **Shopify + WordPress APIs** — Shopify Storefront API for product data, REST integrations for one-click publishing to either CMS.
- **Vercel + Stripe** — Vercel for hosting and edge A/B variant routing. Stripe handles subscriptions and the agency tier billing.

## AI Prompts to Build This

Copy and paste these into Claude, Cursor, or your favorite AI tool.

**1. Project Setup**

```text
Build the weekend MVP of "Pagely": describe a product, an audience and a goal in three short steps and get a responsive landing page from a fixed set of components, which you can edit and publish at its own address. It never makes up proof.

Stack: Next.js (App Router, TypeScript), Tailwind, Supabase (Postgres, Row Level Security, Auth with email magic link), the Anthropic API for the copy and the section plan. Pages are rendered from JSON by a fixed set of components and published under /p/[slug], server-rendered. Deploy on Vercel.

Tables (Row Level Security on, an owner reads only their own rows; published pages are readable by everyone through the public route):
- pages(id, user_id, slug, brief jsonb, status, published_at)
- page_versions(id, page_id, version, sections jsonb, created_at)
- analytics_events(id, page_id, kind, created_at)  kind is view or cta_click

Screens: /login, /pages (the list), /pages/new (the wizard), /pages/[id] (preview, edit and publish), /p/[slug] (the public page).
Env vars (names only): NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY (server only), ANTHROPIC_API_KEY.

Do not build: billing, plans or an agency tier, Shopify or WordPress publishing, custom subdomains, automatic A/B testing, product imports.
Done when: npm run dev starts, you can sign in, and the three tables exist with Row Level Security on.
```

**2. Core Feature**

```text
Build the one feature that proves Pagely: a page that is ready to publish, with copy that only says things the owner gave.
1. The wizard has three steps: the product (name, what it does, price if the owner wants it shown, a link for the call to action), the audience and the goal, and the style (one of a few presets).
2. A server action asks the Anthropic API for a JSON plan: { hero: { headline, subhead, cta_label }, features: [{ title, body }], faq: [{ q, a }], social_proof: [] }. The prompt says to use only facts the owner entered and to leave social_proof empty unless the owner pasted real quotes or numbers.
3. Check in code: strings contain no HTML, the call-to-action link is an https address the owner typed, and every number or price in the copy appears in the owner's input. Drop social_proof entries that are not the owner's own text.
4. Render the plan with a fixed set of Tailwind components (hero, features, proof, FAQ, call to action) that are responsive and meet AA contrast. Show the preview and let the owner edit any text.
5. Save each change as a page_versions row. Publish sets the slug and publishes /p/[slug], rendered on the server so crawlers see it, with a title and description.
6. Record a view and a call-to-action click on the public page as first-party events with no cookies. Show counts on the page's dashboard.
Rules: never invent a testimonial, a statistic, a logo or a guarantee. Never promise a conversion lift anywhere. An unpublished page returns not found.
Empty state: with no pages, show the wizard and a sample brief.
Done when: a sample brief produces a page with no invented numbers, a made-up testimonial is dropped, editing and publishing creates a version and a public page, and views and clicks are counted.
```

**3. Landing Page**

```text
Build a one-page landing site for Pagely, a landing page builder for small online stores.
Hero: "A landing page for your product in minutes." Sub: "Answer three questions. Get a clean, responsive page with copy based only on what you told us. Edit it and publish." One button: Join the waitlist.
Sections: a three-step wizard demo producing a sample page, how it works in four steps (describe, generate, edit, publish), and an FAQ on what the copy is based on (only your input), why there are no made-up reviews and which store connections come next.
Waitlist: store the email in a waitlist table in Supabase. No other service.
Style: Geist, a deep emerald and warm neutrals that feel premium without being intimidating.
Done when: the page renders on a phone and a submitted email appears in the waitlist table.
```
