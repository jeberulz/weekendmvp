## The Problem

DTC brands spend years optimizing checkout trust — SSL badges, review widgets, transparent shipping, Klaviyo flows that feel personal. The shopper crosses the finish line feeling seen. Then they email support about a delayed package or a sizing question, and the experience snaps back to 2014: paste your order number, tell us your email again, wait while an agent (or a bot) pulls up a record that should have been obvious from the first sentence.

The mismatch is not cosmetic. It erodes the brand promise you paid to build at acquisition. A repeat customer who spent $800 across four orders should never hear "What's your order number?" from an AI chat widget sitting on the same storefront that remembered their cart. Support leaders feel this daily in r/shopify and r/ecommerce threads: Gorgias macros help agents type faster, but they do not give the bot a unified memory of orders, returns, loyalty tier, open tickets, and product-level signals (back-in-stock, variant discontinuation, review themes) in one agent-callable payload.

Enterprise CX suites solve pieces of the puzzle at enterprise prices. Zendesk and Salesforce Service Cloud were built for ticket volume and SLA reporting, not for stitching Shopify order graphs to Tidio's bot API in an afternoon. Mid-market DTC teams ($1M–$20M GMV) already run a patchwork: Shopify Admin for orders, Loop or native returns, Gorgias or Intercom for tickets, Klaviyo for marketing context, maybe a spreadsheet for VIP flags. When they turn on AI deflection, each vendor exposes a narrow slice. The bot hallucinates policy or asks redundant questions because nobody owns the **context layer** between commerce data and the helpdesk.

The pain shows up in metrics operators actually watch: repeat-contact rate spikes after bot handoffs, CSAT drops on "where is my order" despite perfect tracking data in Shopify, and agent handle time bloated by tab-switching. Founders describe it as "we look premium until someone hits support." That is the gap Knownly names: not another inbox, but a thin, Shopify-native context API that makes every downstream AI agent sound like it already knows the customer.

## The Solution

**Knownly** (working title: Shopify AI Support Context Layer) is a Shopify app that unifies order history, returns status, open and recent tickets, subscription state, product signals, and lightweight customer traits into a single, agent-callable context object. You keep Gorgias, Tidio, Intercom, or a custom Claude agent on the front lines. Knownly sits underneath as the memory and retrieval layer so bots and copilots stop interrogating repeat buyers and start resolving.

On install, the app connects to Shopify Admin API and registers webhooks for orders, fulfillments, refunds, and customers. Optional connectors pull return labels from Loop, Returnly, or native Shopify returns; ticket summaries from Gorgias or Intercom via read-only API keys; and product metadata (inventory, metafields, review sentiment if you already run a review app). All of this normalizes into a **Customer Context Document** — versioned JSON with stable field names your agents can rely on, plus a compact natural-language summary generated by Claude for LLM consumption.

When a shopper opens chat or sends an email, your helpdesk calls Knownly's context endpoint with email, phone, or Shopify customer ID. Sub-200ms responses return: lifetime value band, last five orders with tracking links, open return RMAs, prior ticket subjects, recommended next actions ("offer replacement size M; order #1042 delivered Tuesday"), and guardrails ("do not promise refund until return scanned"). Agents see the same panel in an embedded Shopify Admin sidebar. AI bots receive a structured tool schema so they fetch context before replying, not after the customer rage-quits.

The MVP is deliberately not a full helpdesk. You are selling **context plumbing** for mid-market DTC: faster time-to-wow on AI support, fewer escalations, and a credible answer to "why does our bot feel dumb?" without re-platforming off Gorgias.

**How it works:**

1. **Install and sync** — Merchant installs the Shopify app; OAuth connects Admin API; webhooks backfill orders, customers, fulfillments, and refunds into Postgres with Shopify IDs as the join key.
2. **Connect helpdesk and returns** — Read-only API keys for Gorgias, Intercom, Tidio, or Zendesk ingest open tickets and recent resolutions; optional Loop or Shopify Returns app links RMA status to order lines.
3. **Build the context document** — On each webhook or nightly reconciliation, Knownly merges commerce, support, and product signals into a versioned Customer Context Document plus a Claude-generated summary block tuned for agent prompts.
4. **Expose agent-callable APIs** — REST and MCP-style tool endpoints let chatbots fetch context by email or customer ID; embedded admin UI shows the same payload to human agents inside Shopify.
5. **Measure deflection and repeat contacts** — Dashboard tracks context fetch latency, bot containment rate, and repeat-contact rate before and after enablement; alerts when stale data exceeds SLA (e.g., ticket closed in Gorgias but still marked open in cache).

Weekend MVP scope: Shopify sync plus Gorgias read-only plus one context API and a sidebar iframe. Ship Frontend tier at $49/seat; upsell Pro automations and Proactive context push on new ticket creation.

## Market Research

Customer experience software is one of the fastest-growing line items in the modern commerce stack — and AI support is accelerating spend without fixing the data fragmentation problem Knownly targets.

- **Customer experience (CX) software** was valued at roughly **$18.28B in 2026** and is projected to reach **$49.56B by 2035**, growing at about **11.73% CAGR**, driven by AI-assisted service, omnichannel expectations, and DTC brands professionalizing support ops ([Business Research Insights — CX software market](https://www.businessresearchinsights.com/market-reports/customer-experience-cx-software-market-120617)).
- **Customer experience management (CEM)** — the broader discipline of measuring and improving journeys — sits near **$22.79B** today with a path toward **$37.23B**, reflecting sustained investment in voice-of-customer, journey analytics, and closed-loop feedback ([Mordor Intelligence — CEM market](https://www.mordorintelligence.com/industry-reports/customer-experience-management-market)).
- **Customer experience platforms** — the integrated hub category incumbents sell — were estimated at **$9.84B in 2024** and forecast to hit **$30.74B by 2032** at roughly **15.3% CAGR**, as teams consolidate point tools ([Credence Research — CX platforms market](https://www.credenceresearch.com/report/customer-experience-platforms-market)).
- **Ecommerce-specific CX pressure** is visible in operational metrics, not just market reports: repeat buyers expect recognition, WISMO ("where is my order") remains the highest-volume contact driver, and AI chat adoption is rising faster than integration quality — creating budget for a lightweight context layer that makes existing bots smarter instead of rip-and-replace ([Thematic — ecommerce CX statistics](https://getthematic.com/insights/ecommerce-cx-statistics-growth-engine)).

For SAM, focus on Shopify Plus and high-Growth stores on Gorgias or Intercom with 2,000–50,000 tickets per year: they already pay for helpdesk seats and AI add-ons, feel the "asked for my order number again" pain acutely, and cannot justify Salesforce-scale implementations. Even 0.5% penetration of active Shopify merchants at $49–$99 per seat per month is a credible path to mid-seven-figure ARR before enterprise white-glove integrations.

## Competitive Landscape

Most competitors own the inbox or the campaign, not the cross-vendor context graph. Position Knownly honestly: you complement Gorgias and Intercom; you do not replace them.

- **Zendesk** — Full-service CRM and ticketing suite with AI agents and extensive marketplace. Strong for enterprises that want one throat to choke. Pricing commonly starts around **$55 per agent per month** on paid tiers, with AI and workforce add-ons pushing bills higher. Gap: Shopify-native context for mid-market DTC requires custom integration work; Zendesk is heavy and expensive for a 15-person support team that only needs unified order plus ticket memory.
- **Freshdesk** — Popular mid-market helpdesk with a generous free tier and paid plans stepping from roughly **$15 per agent** toward **Pro near $49 per agent per month**. Solid ticketing and automation; not a commerce context API. Gap: merchants still manually link Shopify orders or buy middleware; bots lack a first-class Customer Context Document unless you build it.
- **Gorgias** — DTC darling helpdesk deeply integrated with Shopify for ticket sidebar order cards. Plans often start around **$10–60+ per month** depending on ticket volume band, scaling with usage. Excellent for human agents in one UI. Gap: Gorgias is a helpdesk, not an vendor-neutral context layer — Tidio bots, Intercom Fin, or a custom Claude agent outside Gorgias do not automatically inherit the same enriched payload unless you pay for and wire their specific integrations.
- **Intercom** — Conversational support and Fin AI with strong messaging UX; pricing varies by seats and resolution volume, typically landing in the same league as premium helpdesks for growing teams. Gap: commerce context depth depends on productized Shopify connectors; cross-stack returns and multi-app signals still fragment without a dedicated context service.
- **Klaviyo** — Dominant owned marketing with excellent customer profiles for email and SMS. Free entry with **volume-based pricing often from ~$20+ per month** scaling with contacts. Gap: Klaviyo is marketing-first, not real-time support context for open tickets, RMA status, or agent copilots; using it as a support brain creates compliance and freshness issues.
- **DIY (Shopify Flow plus spreadsheets plus Zapier)** — Cheap on paper, expensive in drift. Zaps break on API changes; no sub-200ms context endpoint; no agent tool schema. Gap: fine for three macros, unusable for AI deflection at scale.

**Your Opportunity**

Win as the **thin context layer** for mid-market DTC: stitch Shopify plus returns plus tickets plus product signals into one agent-callable API without forcing a helpdesk migration. Incumbents optimize their own inbox or campaign graph; they will not prioritize vendor-neutral MCP-style tools that also serve Tidio and custom agents. Moat accrues from normalized schemas across connectors, latency SLOs, and audit logs that prove the bot saw the same facts the human would — critical when AI refunds and replacements face chargeback scrutiny.

## Business Model

Seat-based SaaS aligned with how support teams already budget, plus high-margin services for custom integrations.

- **Frontend** (~**$49 per seat per month**) — Core Shopify sync, Customer Context API, embedded admin sidebar, Gorgias or one helpdesk connector, 10k context fetches included, email support.
- **Pro** (~**$99 per seat per month**) — Unlimited fetches, multiple helpdesk connectors, proactive context push on ticket create, Claude summary tuning, returns app connectors (Loop, native Shopify Returns), webhook streaming to custom agents, priority support.
- **Custom integration** (**$500–$2,000** one-time) — Bespoke ERP, 3PL, or loyalty system fields; custom tool schema for in-house LLM stacks; sandbox plus production cutover.
- **White-glove onboarding** (**$1,500** one-time) — Done-for-you connector setup, prompt pack for Fin or Tidio, baseline metrics workshop, 30-day repeat-contact review.

**Unit Economics (illustrative)**

- **~$65** — Blended ARPU (mix of Frontend and Pro seats)
- **~$8** — Infra plus LLM summary cost per seat at steady state (cache aggressively on unchanged orders)
- **~88%** — Gross margin target at 50+ stores
- **~$780** — LTV at 12-month life and 5% monthly logo churn

Path to **$10K MRR**: ~154 seats average, or 100 stores at 1.5 seats each — realistic for Gorgias-heavy Shopify merchants after 10 case studies showing repeat-contact reduction. Expansion revenue from custom integrations funds connector library depth (Recharge subscriptions, Yotpo VIP tags) without bloating core SKU.

## Recommended Tech Stack

Optimize for Shopify-first data fidelity, fast context reads, and helpdesk-agnostic APIs.

- **Next.js Shopify App (App Bridge plus Polaris)** — Embedded admin UI, OAuth install flow, billing surfaces, sidebar panel for human agents. Deploy on **Vercel** with edge caching for static assets.
- **Shopify Admin API plus webhooks** — Orders, customers, fulfillments, refunds, inventory snapshots; mandatory webhook HMAC verification and idempotent workers.
- **Postgres (Neon or Supabase)** — customers, orders, fulfillments, returns_links, ticket_summaries, context_documents with version and as_of timestamp; index by shop_id plus email plus shopify_customer_id.
- **Claude (Anthropic API)** — Generate compact NL summaries and suggested next actions from structured context; prompt-cache stable system instructions; only re-summarize when underlying facts change.
- **Stripe Billing** — Seat-based subscriptions for Frontend and Pro; one-time Checkout for custom integration and white-glove SKUs; metered overage optional above included context fetches.
- **Redis (Upstash)** — Hot cache for context documents; rate limits per shop; short TTL invalidation on webhooks.
- **Background jobs (Inngest or BullMQ)** — Webhook ingestion, connector sync, nightly reconciliation against Shopify as source of truth.
- **Helpdesk SDKs** — Read-only clients for Gorgias, Intercom, Zendesk; normalize to internal ticket_summary schema; never write tickets in v1 except optional private notes behind feature flag.

Security posture: encrypt OAuth tokens at rest, scoped read-only helpdesk tokens, SOC2-friendly audit log of every context fetch (who asked, which customer, which fields returned). DPA and GDPR delete on customer redact webhooks from Shopify.

```text
- context_documents(id, shop_id, customer_ref, payload_json, summary_text, as_of, stale boolean)
- webhook_events(id, shop_id, topic, customer_ref, received_at)

Screens: /login, /shop (connect the store and create an API key), /lookup (try a customer), /log (hits, misses and latency).

Do not build: billing or seats, OAuth app installation or App Bridge, helpdesk connectors for Gorgias, Tidio or Intercom, Redis, a job queue, a sidebar extension.
Done when: npm run dev starts, you can sign in, and the four tables exist with Row Level Security on.
```

**2. Core Feature**

```text
Build the one feature that proves Knownly: a context summary that is quick, right and never invents an order.
1. GET /api/v1/context takes an email, a customer id or an order name and a shop API key (compare against api_key_hash). Reject a bad key.
2. Load the customer's last 5 orders from the Shopify Admin API with their financial status, fulfillment status, tracking and refund state, and any return in progress. Build a structured payload from only those fields.
3. Return the cached context document when its as_of is under 5 minutes old and it is not marked stale. Otherwise refetch, rebuild the payload and save it.
4. Send the payload to the Anthropic API with a strict JSON schema { summary: string of at most 120 words, suggested_actions: string[], guardrails: string[], do_not_say: string[] }. Send no phone number, address or email, only order names, statuses and dates.
5. Check in code that every order name in the summary exists in the payload. If not, return the structured payload with a plain template summary instead.
6. A Shopify webhook route (orders create, orders update and refunds create) verifies the HMAC signature with SHOPIFY_WEBHOOK_SECRET, records the event and marks that customer's document stale.
7. Log every request's cache hit and latency. Serve the same fields as a tool definition at /api/v1/tool for an agent to read.
Rules: never return another customer's data for a lookup. Never include payment details. A demo mode serves fixture customers so you can test without a store.
Empty state: before connecting a store, show the connect form and demo mode.
Done when: a lookup by email returns the last orders and a summary whose order names all exist, a second call within 5 minutes is a cache hit, a signed webhook marks the document stale and a bad signature is rejected.
```
