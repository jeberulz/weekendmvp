## The Problem

Coordinating a large wedding means a guest list in one app, a schedule in another, RSVPs in email, and updates in a group chat half the guests have muted. Corporate retreats and family reunions run the same patchwork. The organizer becomes the integration layer, copying data between tools never designed to work together. Incumbent coordination platforms exist — Whova, Cvent, EventMobi — but they sell monthly subscriptions for events that last a weekend. The shape of the pricing doesn’t match the shape of the use case.

## The Solution

Organizers fill out a short intake form, pick a template (wedding, corporate retreat, reunion), upload branding, and within hours receive a shareable link. Guests open the link to find the schedule, RSVP, share photos, and receive updates as details change. Wedding planners get a deliverable that looks custom-built. Corporate coordinators get a single URL replacing the pre-event email chain. After the event, the app archives into a static keepsake page the organizer keeps.

**How it works:**

1. **Pick a template** — Wedding, corporate retreat, or family reunion
2. **Brand and share** — Logo, colors, event details → shareable link in hours
3. **Expire + archive** — After the event, app freezes into a static keepsake page

## Competitive Landscape

Two clusters: enterprise event platforms priced for recurring conferences (Cvent, Whova, EventMobi, Bizzabo) and scattered point tools for weddings (Zola, The Knot). Nobody prices per-event for one-off weddings, retreats, and reunions. The pricing shape mismatch is the opening.

- **Cvent / Bizzabo** — Enterprise event platforms. Rich feature set built for recurring corporate conferences. $5K+ annual contracts; onboarding assumes a dedicated event-ops team. $5K–$50K/yr annual contracts
- **Whova / EventMobi** — Mid-market mobile event apps. Strong for conferences and multi-day corporate retreats; awkward for weddings and family reunions where the shape is different. $1,500–$5,000 per event (Whova starts “custom”)
- **Zola / The Knot** — Wedding-specific consumer brands. Strong for registries and websites; weaker on real-time day-of coordination and guest app behavior. Free ad-supported model caps brand polish. Free with upsells; wedding-only
- **Generic tools (Google Docs, WhatsApp, Eventbrite)** — The status quo. Works but fragmented. Each organizer becomes the integration layer. The Knot’s 2024 Real Weddings Study found organizers juggle 5+ tools per wedding. Free; the cost is the organizer’s time

**Your Opportunity**

Per-event pricing that matches the shape of the use case: $150-$300 per wedding, $500-$1000 per corporate event, $50-$100 per family reunion. Add a $25/mo subscription for frequent organizers and a $10K+/yr agency tier for wedding planners. Cvent’s annual-contract tilt and Whova’s enterprise shape are both the opening.

## Recommended Tech Stack

Templates are the product. Next.js handles multi-tenant routing via a wildcard domain; each event app lives at `\{slug}.dayframe.app`. Supabase stores the event config; Cloudflare R2 stores uploaded media cheaply. AI customization for brand colors is a nice touch but intake-to-launch speed earns referrals. Ship three hand-built templates first.

- **Next.js 14 multi-tenant** — Wildcard subdomain routing via middleware; each event app reads its config from Supabase and renders the right template. Static generation at publish time for maximum speed.
- **Supabase** — Auth + Postgres for events (template_id, slug, brand_colors, schedule_json, guests, expires_at), rsvps, photos. RLS per event owner.
- **Cloudflare R2 + Images** — Cheap object storage for uploaded photos and media. Cloudflare Images for automatic resizing of guest photo uploads. Zero egress fees.
- **Claude (optional polish)** — Generate brand-aligned color palettes from uploaded logos, write default welcome copy in the organizer’s tone. Nice-to-have; not MVP-critical.
- **Resend** — Guest invitations, RSVP confirmations, day-of reminders, post-event “your keepsake is ready” email. React Email templates per event template.
- **Stripe + Vercel Cron** — Stripe Checkout for per-event purchases, Stripe Billing for the Agency subscription. Nightly Vercel Cron flips expired events into keepsake archive mode.

**1. Project Setup**

```text
Build the weekend MVP of the "Single-Event App Builder": an organizer fills a short form and gets a mobile event page for a wedding with a schedule, RSVP and guest photos, and after the event it freezes into a keepsake page. One template, one link per event.

Stack: Next.js (App Router, TypeScript), Tailwind, Supabase (Postgres, Row Level Security, Storage, Auth with email magic link for organizers), Resend for RSVP confirmations and the keepsake email. Event pages live at a path, with no wildcard domains. A Vercel Cron route runs the nightly expiry. Deploy on Vercel.

Tables (Row Level Security on, an organizer reads only their own events; the public event page and guest forms go through server routes):
- events(id, user_id, template, slug, name, event_date, timezone, brand jsonb, schedule jsonb, cover_path, status, expires_at)  status is live or keepsake
- rsvps(id, event_id, guest_name, email, attending, plus_one boolean, dietary, song, created_at)
- photos(id, event_id, storage_key, uploader_name, status, created_at)  status is pending, approved or removed
- keepsakes(id, event_id, snapshot jsonb, published_at)

Screens: /login, /events/new (the intake), /events/[id] (RSVPs, photo approvals and editing), /e/[slug] (the guest page), /k/[slug] (the keepsake).
Env vars (names only): NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY (server only), RESEND_API_KEY, CRON_SECRET.

Do not build: billing, per-event or monthly pricing, wildcard subdomains, corporate and reunion templates, automatic photo moderation, a registry integration.
Done when: npm run dev starts, you can sign in, and the four tables exist with Row Level Security on.
```

**2. Core Feature**

```text
Build the one feature that proves the builder: a guest-ready wedding page in minutes, and a keepsake that lasts.
1. The intake takes the event name, date and timezone, a cover photo, two brand colors, schedule items and optional travel and stay notes and registry links (https only). Create a slug that cannot be guessed and email the organizer the guest link.
2. The wedding page is mobile first: a hero with a countdown, the schedule, an RSVP form (attending, plus-one, dietary needs, a song request), a guest photo wall, travel and stay notes and registry links. Set it to noindex.
3. Guests upload photos without an account, up to 10 MB each, jpg or png. Remove all location data from every image on upload. New photos are pending until the organizer approves them in a queue. Only approved photos show.
4. An RSVP sends the guest a confirmation through Resend. The organizer sees RSVPs and downloads them as a CSV.
5. A nightly cron route (protected by CRON_SECRET) finds events 30 days past their date. For each, save a static snapshot of the schedule and the approved photos, set the event to keepsake, switch /e/[slug] to read-only and email the organizer the permanent keepsake link.
6. The keepsake page shows no forms and no guest emails or RSVPs.
Rules: guest contact details are never public and never in the keepsake. The organizer can delete the event and everything on it. Say that on the intake form.
Empty state: a new event shows the guest link and a checklist (add the schedule, upload a cover, share the link).
Done when: a sample event takes RSVPs and sends confirmations, an uploaded photo has no location data and stays hidden until approved, the nightly route turns an old event into a keepsake with no guest emails and the organizer's delete removes the photos.
```
