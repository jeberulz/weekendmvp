## The Problem

Photographers still buy static preset packs on FilterGrade and Creative Market, slam them onto a wedding set, and then spend forty minutes undoing the orange. Adobe already ships Adaptive Presets inside Lightroom Classic / CC and owns 80%+ of the pro share. Evoto sells AI retouching as a subscription or pay-as-you-go. A "Lightroom Preset Builder" plugin exists as freemium / one-time. None of them take *this* shoot — this skin, this gym, this cloudy 4pm — and emit an XMP that matches a reference the shooter actually likes.

r/photography (5.5 million) and r/Lightroom (370k) are the complaint department. Facebook's Photoshop and Lightroom group (390k) and Beginners Photography (917k) are the volume. The beginner buys a $29 pack and thinks they did something. The shooter who invoices $3,000 wants a recipe they can reuse next Saturday.

The hidden cost is inconsistency across a gallery. One preset that looked right on the ceremony aisle wrecks the reception tungsten. Adaptive Presets help. They still do not start from *this couple's* skin and *this* venue's gel. That is the support ticket you will get, and the reason the product has to emit sliders — not a baked JPEG they cannot undo.

## The Solution

Upload 3–8 selects plus a reference image (or a named look: "editorial indoor, 5200K, low sat skin"). Get a Lightroom XMP / DNG profile, a before/after, and a one-line "what this preset actually does" so they can tweak. $15 Starter / $30 Pro in the Ideabrowser ladder. Marketplace add-on at $10 if you later let shooters sell their generated packs — that is year two.

**How it works:**

1. **Shoot lock** — Upload selects. The app reads EXIF (WB, camera, lens) and refuses to pretend a phone JPEG is a raw wedding file.
2. **Look lock** — Reference photo or a constrained look picker. No "make it cinematic" text box.
3. **Emit XMP** — Predicted slider recipe (WB, tone curve, HSL, color grading, grain). User downloads XMP, applies, and can nudge. Pro unlocks batch across a folder.

Privacy is a ship-blocker. These are client faces. 24-hour TTL on uploads, no training, no "community lookbook" of weddings. If you skip that, you do not have a photography product. You have a leak.

## Competitive Landscape

- **Adobe Lightroom Adaptive Presets** — inside the CC subscription. 80%+ pro share. Good, generic, not "from my reference photo."
- **Evoto AI** — subscription / PAYG. Retouching, not XMP recipes.
- **Lightroom Preset Builder plugins** — freemium or one-time. Manual slider work with a nicer UI.
- **FilterGrade / Creative Market** — static packs. The incumbent the buyer already regrets.
- **Luminar Neo, ON1, VSCO, Prisma** — indirect. Different catalogs, same "buy a look" motion.

**Your Opportunity**

Free preview (3 sliders, no XMP) → $15 Starter (one XMP) → $30 Pro (batch + DNG profile) → $10 marketplace take-rate later → $10k+/year if a school or a brand studio wants seats. Do not fight Adobe on catalog. Fight FilterGrade on "this was built from *my* files."

YouTube is the channel: one preset-from-reference tutorial a week, XMP attached for Pro buyers. Reddit will call it a gimmick until a shooter posts a slider map that matches what they would have dialed. That post is the launch.

## Recommended Tech Stack

- **App:** Next.js 15 on Vercel
- **Auth / billing:** Clerk + Stripe
- **Storage:** R2 for selects (short TTL — these are client photos)
- **DB:** Supabase — `looks`, `generations`, `xmps`
- **Models:** vision model to estimate WB/tone/HSL deltas vs reference; emit numeric sliders, not a baked JPEG
- **XMP:** a tested template per Lightroom version (Classic vs CC)

**1. Project Setup**

```text
Build the weekend MVP of the "Lightroom Preset Generator": pick a reference look and a few photos from a shoot, and get a Lightroom preset file whose sliders are worked out from how the images differ, with a plain-English list of what each slider does. Photos are read in your browser and never uploaded.

Stack: Next.js (App Router, TypeScript), Tailwind, Supabase (Postgres, Row Level Security, Auth with email magic link) for saved looks and generations only, exifr to read camera data and the canvas API to measure each image, in the browser. The preset file comes from a versioned template. Deploy on Vercel.

Tables (Row Level Security on, each user reads only their own rows; photos are never stored):
- looks(id, user_id, name, reference_stats jsonb, created_at)
- generations(id, user_id, look_id, shoot_stats jsonb, sliders jsonb, created_at)
- xmps(id, generation_id, file_path, lightroom_version, created_at)

Screens: /login, /generate (the reference, the selects, the sliders and a before and after), /looks, /history.
Env vars (names only): NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY (server only).

Do not build: billing, plans or a marketplace, a vision model, white balance or tint changes, batch processing, storing any photo.
Done when: npm run dev starts, you can sign in, and the three tables exist with Row Level Security on.
```

**2. Core Feature**

```text
Build the one feature that proves the Generator: sliders you can explain and undo, from measurements instead of a guess.
1. Take 3 to 8 selects and one reference image in the browser. Read EXIF with exifr and show a warning, not a rejection, for a file with no camera make ("phone or edited JPEG: results will be rougher").
2. Measure each image on a canvas: the luminance at the 5th, 50th and 95th percentiles, the spread of luminance as contrast and the mean saturation. Keep only these numbers, never the pixels. Average the selects into one shoot profile.
3. Map the difference between the reference and the shoot to sliders with formulas kept in one documented file with clamps: Exposure, Contrast, Highlights, Shadows, Whites, Blacks, Vibrance and Saturation. Leave white balance and tint alone and say why: they belong to each photo. Unit test the measuring and the mapping with fixture images.
4. Show a before and after on a preview by applying the same simple adjustments to the canvas, labeled "an approximation, Lightroom's own engine will differ".
5. Write the preset as an XMP file from a versioned template for Lightroom Classic 13 or later, using the standard camera raw setting names for the sliders above. Save the sliders and the file.
6. Show a "what this preset does" panel that lists each slider and its value in plain English ("Shadows +18: lifts the dark areas a little") so the shooter can nudge it in Lightroom.
7. Test by importing the file into Lightroom Classic and checking that the sliders move to the listed values.
Rules: no image leaves the browser. Say so on the page. Never promise the preset reproduces the reference exactly.
Empty state: before any upload, show the two drop zones and what makes a good reference.
Done when: the measuring and mapping tests pass, a sample reference and three selects produce a preset whose slider values match the panel, Lightroom accepts the file and no network request carries an image.
```
