## The Problem

Bootcamp completion rates determine enrollment numbers, and enrollment determines revenue. Completion depends on whether students get unstuck fast enough to keep momentum through the program. The instructor is the only feedback mechanism, and every minute a student waits for help is a minute closer to falling behind permanently.

The classroom has a structural blind spot. A student who is quietly stuck looks identical to a student who is quietly working. The ones who need help most are often the least likely to raise a hand. By the time an instructor notices, the student has spent twenty minutes spiraling on a missing bracket and decided they are just not cut out for this.

The business model runs on a feedback loop the school has no tool to measure. A program that moves completion from 70 to 80 percent keeps an additional cohort worth of tuition that would otherwise be refunded or lost to dropout, but no off-the-shelf tool gives instructors a live view of where the room actually is.

## The Solution

Handraised sits inside each student VS Code editor and watches what they write in real time. When a student stops typing, hits a repeated error, or falls behind the class pace, the system flags them on the instructor live dashboard. The student receives a contextual hint that explains the problem without giving away the answer.

The instructor sees a room-wide view: who is progressing, who is stuck, and who stopped working five minutes ago without asking for help. The hint engine teaches rather than solves, so it supports the curriculum instead of short-circuiting it. The product lives or dies on instructor trust, so accuracy of the flags is the core metric from day one.

**How it works:**

1. Build the VS Code extension that streams lightweight progress signals (typing pauses, diagnostics, test pass rate) to a central room session.
2. Build the instructor dashboard: a live grid of students color-coded by progressing, stuck, or idle, with drill-in on the blocking error.
3. Add the hint engine that explains the problem without giving the answer, and a feedback control so instructors rate each flag for accuracy.

## Competitive Landscape

Existing classroom tools manage assignments and submissions. None give the instructor a real-time map of who is stuck right now, which is the exact moment intervention matters.

- **GitHub Classroom** (Free) — Great for distributing and collecting assignments, but offers no live, in-progress signal of who is struggling.
- **Replit Teams for Education** (from $20/mo) — A shared coding environment, but instructors still cannot see real-time stuck signals across a whole room.
- **Generic LMS (Canvas)** (Institutional) — Tracks grades and submissions after the fact, not the live moment a student is blocked.
- **Manual TAs** ($$$ labor) — The current solution. Effective but does not scale and cannot watch every editor at once.

**Your Opportunity**

The unmet need is a live, room-wide view of student progress tied to contextual hints. Instructor adoption plus accurate flags creates a data advantage that compounds across cohorts and is hard for a generic LMS to replicate.

## Recommended Tech Stack

The build is a streaming extension plus a real-time dashboard. Keep the signals lightweight so the privacy story is clean and the latency is low; the AI only runs when a student is actually stuck.

- **VS Code extension (TypeScript)** (Client) — Runs in the environment students already use and streams only progress signals, not keystrokes.
- **Supabase Realtime channels** (Realtime) — Powers the live instructor grid with per-room presence and status updates out of the box.
- **Claude for hint generation** (AI) — Produces hints that explain the blocking problem without revealing the answer, on demand.
- **Next.js + Tailwind** (Dashboard) — A fast instructor view that color-codes the room and drills into any student blocker.

**2. Core Feature**

```text
Build the one feature that proves Handraised: an instructor can see who is stuck right now, and a student can get a hint that teaches.
1. The extension asks for a room code and a display name and shows a notice of exactly what it sends: whether you typed in the last minute, how many errors are open, an optional test pass rate and the text of the first error message. No code and no keystrokes.
2. Every 15 seconds it posts a signal through a server route that checks the room code. Read errors from the editor's diagnostics. Read the pass rate from a test results file if the room sets one.
3. The dashboard subscribes to the room with Supabase Realtime and shows a grid of students. Decide each status in code: progressing (green), stuck (amber) when the same error appears in 3 signals in a row or the student has been idle for 5 minutes with open errors, and idle (grey) when idle for 5 minutes with no errors. Show the status as a word as well as a color. Clicking a student shows their current error message.
4. Ask for a hint is a student button. It shows the error message and up to 15 lines around the error, and sends them only after the student confirms. The Anthropic API returns JSON { concept, hint }. Reject a hint that contains a code block or more than 4 sentences, and ask once more.
5. Each time a student is flagged stuck, the instructor can mark it accurate or not accurate. If more than 30 percent of at least 10 flags are marked not accurate, show a prompt to loosen the thresholds one step and apply it when accepted.
6. Unit test the status function and the flag tuning, and test the extension's signal builder with a mocked editor API.
Rules: send nothing that is not in the notice. Never give the answer, only the concept and a nudge. Say how to leave the room.
Empty state: a new room shows its code in large type and the install steps.
Done when: three simulated students show green, amber and grey correctly, a repeated error turns amber on the third signal, a hint with a code block is rejected and 4 of 10 not-accurate flags raise the recalibration prompt.
```
